## Changes to measure

- Press **F8** for stage timings: culling, residency, ownership, commands, uploads, integration, GPU submission, total LOD CPU, and 240-frame mean. Worker times are listed separately. The `missing in 16K disk` number measures *drawable* 128-block cells at the last ownership publication. A `NEAR PENDING` label concerns requested refinement, not proof of a sky hole.
- Press **F9** to toggle Everview drawing and uploads while leaving existing residency allocated. After all generation completes, compare on/off frame time and FPS from one stationary viewpoint. Toggle back, rotate 180 degrees twice, and observe the same LOD quality with no new upload or plan work due only to yaw.
- Fly through already generated terrain at various speeds (including the reported 3× setting), checking the 16K drawable-cell count, shoreline boundaries, gaps, draw calls, GPU memory, command reuse, and vanilla/LOD handoff. Test high above terrain and along the vanilla visibility edge.
- Repeat the test after moving beyond the old view and returning. Check newly loaded terrain while the coarse floor streams; cold world generation cannot provide terrain which has not yet been generated.
- Compare M9.5 and M9.6 from the same world, location, view distance, render settings, and shader status. Wait for each build's initial fill to complete before recording settled performance. Record FPS, culling/residency/ownership/command/upload/integration/submission timings, total LOD CPU, CPU/GPU LOD memory, and draw counts.
- Test mountains, ridges, narrow peaks and valleys, islands, rivers, shallow shores, and ice. Simplification bounds error against *sampled* heights; a feature narrower than the worldgen sample spacing may still be missed. The 16-block final L6 lattice and existing focus spacing remain limitations.

The height and shoreline source changed to ocean-floor plus a selective surface query for ambiguous shallow columns. Cache v34 is intentionally separate. The first M9.6 launch must generate new tiles; the M9.5 cache remains available for rollback. Do not compare a cold M9.6 world against a warm M9.5 cache as if generation were settled.

## Architecture and current limits

GPU regions, ownership commands, and terrain edges stay resident independently of visibility. Region source changes launch bounded CPU packing; a render-state transaction holds previous buffers until ownership and terrain joins are ready. An uploaded coarser parent is mandatory before retiring a resident child. The outer floor remains pinned within the coverage guard, and the hard GPU budget counts old and new buffers simultaneously. Missing *ungenerated* floor cells are reported explicitly instead of being concealed.

The error-bounded quadtree mesher retains sampled extrema and splits mixed wet/dry cells into sample-owned footprints. Where adjacent drawable height profiles differ, the transaction joins their actual heights rather than drawing an unrelated blanket. The fast region packer avoids per-quad object creation on aligned far terrain. Material IDs and packed face normals persist with region metadata, and a backend interface permits future material/shader attachments within the existing opaque pass. Iris shader-pack integration is not implemented or validated in this release.

Java 25 CI runs `./gradlew build` with the existing concurrent compaction regression, nine architecture checks (shorelines, error, extrema, residency and budget) and three seam tests. A CPU-only runner in `ArchitectureChecks.main` additionally prints a flat tile's emitted quads and mesher time; that result excludes world generation, GPU submission, and Minecraft FPS.
