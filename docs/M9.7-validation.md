# M9.7 shared source and adaptive detail

Branch: `dev/m9.7-shared-source-adaptive-detail`. Based on M9.6 `7d15441950e81c5d63adfd60f2dd875562fd2798`. No main merge.

## Implementation

- Exact Minecraft 26.3 density/aquifer sampling now shares a 16×16 density context instead of creating one context per height query. Ocean floor and fluid surface are computed together. A world-scoped source store shares in-flight fills and persists columns independently of LOD meshes.
- The source retains signed solid-floor and surface heights, wet state/depth (surface minus floor), and a separate solid material/tint. Rendering water no longer destroys the underlying seabed information. Materials remain the existing biome-based approximation, not full surface-rule or structure generation.
- Source RAM has a strict 32,768-page admission bound (~80 MiB payload/estimated metadata). Dirty writes apply backpressure on workers. Failed I/O cannot grow the cache indefinitely. Checksummed compressed pages are indexed in 256-block disk regions; writes compact when the region log exceeds 2 MiB. Cache v35 is separate from M9.6 v34.
- L1 uses exact block terraces and greedy same-height/material/wet-state merging. A single low-priority detail worker progressively refines exposed L2–L6 terrain in 128-block patches, after the coverage floor is established. Sampling targets use projected size, shoreline state and relief, rather than a fixed ring detail ceiling.
- Adaptive detail requests 1/2/4-block samples. Flat areas can retain 1-block data with very few quads. Complex patches obey a 260,000-quad tile ceiling, divided between their patches: they fall back to 2/4/8/16-block geometry while retaining the finer source. F7 reports this limit explicitly. A settled limited tile is not rebuilt repeatedly; approaching it can request a finer distance target. These targets are not an error certificate for unsampled terrain features.
- Coverage geometry assembly moved off the server tick into existing coverage workers. Source appearance and biome results are reused. Each job captures its world cache so a late old-world job cannot insert into the new world's biome/source cache.
- An optional, versioned, checksummed layer envelope provides a bounded path for future subsurface/volume data. It performs no cave generation, allocation or rendering while inactive. Texture, PBR, trees and structure rendering remain later work.

## Ownership and seams

The reproduced code-level failure paths were:

1. Vanilla CPU handoff masks applied only to L1–L3; farther fallback geometry could reach active vanilla columns.
2. The combined seam buffer bypassed vanilla ownership entirely.
3. Old stability/grace behavior deliberately retained coplanar LOD overlap.
4. Exact and adaptive patch walls could duplicate transition walls; internal patches in a single tile were excluded from seam joining.
5. A generated/compiled section was treated as ready without checking vanilla's actual GPU slices. Preparing the final mask at COLLECT_SUBMITS could also precede the frame's final terrain preparation.

All terrain, water, fallback and seam shaders now use the same final 16-block vanilla ownership mask. Fully owned near batches are removed from CPU submission; mixed/far region fragments are rejected by the shared shader before they write color/depth. Persistent commands remain reusable across ownership changes because the shared mask is bound afresh for the frame. Shader masking is an explicit ownership gate, not a depth-test workaround or an enlarged exclusion ring.

The mask is finalized after vanilla/Sodium terrain preparation, before the main render pass. Vanilla readiness checks the installed mesh and every nonempty layer's actual vertex/index slices, including translucent water. Sodium 0.9.2's overridden readiness path reads installed region state; its synchronous `uploadResults` transaction has finished at this hook. Camera culling does not delete source, resident regions or commands. Section readiness is spatial GPU availability, not whether an occluded section was drawn this camera frame.

The mask is granted after the surface probe sections for a loaded column are ready. This remains a surface-column model, not volumetric cave ownership. Partial section rebuilds, tall cliffs and modded terrain must be checked in game. All old overlap timers and normal terrain depth bias have been removed from this renderer. Terrain and transition buffers switch as one existing M9.6 transaction; replacement command ranges exclude obsolete fine/fallback geometry. Patch boundary walls now belong to the seam transaction, including internal 128-block patches.

The uploaded fallback floor remains available beneath masked vanilla columns. When vanilla unloads, clearing the mask reveals that already uploaded geometry immediately. This guarantee requires established Everview GPU coverage. Cold start, teleporting beyond generated terrain, or a renderer upload failure can still lack replacement data; this pass does not hold Minecraft chunks loaded indefinitely to conceal that condition. F8's drawable-gap count and F7 ownership probe distinguish it from a seam gap.

Region-local vertices and camera-relative transforms are preserved. Eliminating duplicate representations addresses the demonstrated near-coplanar failure. No depth bias, projection replacement, logarithmic depth or shader-pack depth rewrite was introduced. Extreme-distance depth precision and Iris shader packs still require live validation.

## M9.7.1 startup hotfix

The supplied Minecraft 26.3 crash report identified an invalid `LevelRendererMixin`
selector: the new ownership-finalization injection named `renderLevel`, while
the actual target class names the method `render`. The injection now uses the
complete 26.3 method descriptor. Its position remains immediately before
`addMainPass`, after both direct and indirect chunk preparation paths. Required
injection counts remain enabled; ownership masking is not bypassed.

Compilation and the existing headless architecture/shader tests did not apply
the mixins and therefore missed this startup error. The new `mixinSmoke` task
initializes Fabric Loader's real client Knot loader against the packaged mod,
discovers all configured client mixins, loads their targets through the Mixin
transformer, verifies every required injected handler and checks the installed
drawable-readiness interface. It does not initialize Minecraft or a graphics
device. CI gates this both with Fabric API alone and with Sodium 0.9.2+mc26.3.

Locally the old delivered M9.7 JAR fails this test with the exact reported
`everview$finalizeOwnership` / `renderLevel` error. The corrected JAR passes
all four configured mixins and six handlers, both with and without Sodium.
This establishes the startup transformation fix; full modpack startup,
in-world visual correctness and live FPS still need the test client. Terrain
generation, source reuse, GPU residency and ownership architecture are unchanged.

## M9.7.2 first-draw pipeline hotfix

After M9.7.1's selector fix, the supplied report reached the first terrain draw
and failed in `EverviewGpuPipeline` initialization. Minecraft 26.3's
`withVertexShader(String)` and `withFragmentShader(String)` call
`Identifier.withDefaultNamespace`, so the string `everview:core/terrain` becomes
the invalid identifier `minecraft:everview:core/terrain`. Both stages now use
the `Identifier` overload with an explicit Everview namespace and shared
`core/terrain` path.

The packaged Fabric smoke test now executes the production terrain pipeline's
static initializer, validates both shader identifiers against assets in the
same JAR, and checks depth writes and the Globals/Projection/DynamicTransforms/
EverviewOwnership bindings. The old delivered M9.7.1 JAR reproduces the exact
`IdentifierException` in this extended test. The corrected JAR passes both
Fabric-only and Sodium runs. The EGL shader check now reads the shaders from
the built production JAR in CI, rather than testing only source-tree files.
Minecraft's pipeline cache was also inspected: it lazily compiles custom
pipelines on first lookup, so no additional pipeline registration is needed.

These checks cover the reported first-draw initializer failure and packaged
shader validation. They do not claim a full graphical client or modpack run.
No generation, mesh, residency, ownership-mask or draw-command behavior changed.

## M9.7.3 coverage pipeline and source throughput

The user's F8 capture showed 35/2,947 tiles after 52.5 seconds (~0.7 tiles/s) with low renderer CPU cost. F7 then showed one of eight height workers active, 8,012 pending source writes and a sampling rate around 20,300 new columns/s. These captures establish underfilled terrain and low instantaneous worker use; they do not measure a settled full-residency FPS baseline.

Targeted lifecycle inspection found completed detached coverage heights still waiting for the single `currentJob` lane before appearance/mesh assembly. Finished height requests occupied the limited producer slots without progressing to publication. M9.7.3 chains height completion directly to worker assembly and client integration. Slots remain bounded through integration. Coverage can borrow unused exact-worker capacity, after reserving exact tiles' workers; frame pressure still throttles new work and the total worker count is unchanged. Current-lane bootstrap sampling also stays off server ticks. Epoch, cancellation and job-identity checks reject obsolete meshes both before queueing and at integration, including same-key replacement jobs.

Wide strided density volumes were measured and rejected: Minecraft's interpolated samplers evaluate the dense bounding grid between requested columns. The retained implementation instead reuses at most 32 noise/aquifer contexts per worker over 64-block areas for 8/16-block sampling, evaluating one requested column at a time. Contexts close at job completion/cancellation and eviction. Wider spacing retains scalar sampling; dense 16-block pages and world source reuse remain intact. No speculative columns or other source pages are filled while holding a source page lock.

The source writer's old 128-page / 2-second schedule imposed a 64-pages/s ceiling. It now drains bounded background batches (at most 1,024 pages and a 50 ms time window, with 100 ms between batches), keeping the same low-priority writer, checksums and hard source RAM bound. Individual page lock/I/O operations can exceed a batch deadline; render-thread work is not introduced. A focused check saves 600 sparse pages plus appearance data without calling `flush`, then reopens and verifies the saved contents.

The new `sparseSamplingBenchmark` uses the actual prior scalar source path and current loader with identical source lookup/profiling work, alternates execution order, and records four trials after four warmups. Each trial requests a 17×17 lattice, including negative-coordinate tile boundaries. All results must match and resident revisits must generate zero noise. The separate equality checks compare 2,180 sparse requests, plus unaligned points, directly against Minecraft's floor/surface queries and require both wet and dry terrain.

F7 now separates capture/height/assembly/ready stages, bounded producer slots, noise context counts, shared-context columns, total integrated tiles and source pages saved. Generation worker utilization includes coverage assembly; rate counters reset with the world profile. Generic-generator dense timing no longer double-counts individual column work.

Focused production lifecycle checks cover publication while the current lane is blocked, canceled/old-world completions, same-key replacement and idle-worker borrowing under exact reservations/frame pressure. The final CI gate also retains ownership/seam/retirement tests, production shader framebuffer cycles, persistent command scaling, both terrain benchmarks, and packaged Fabric/Sodium pipeline initialization. Renderer ownership, persistent GPU ranges and transactional seam submission are unchanged by this patch.
